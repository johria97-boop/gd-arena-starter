# GD Arena API Contract - v0.7 (automatic discussion flow)

Base URL: `http://localhost:4000/api` locally. JSON over HTTPS in production,
except for the explicitly documented binary Alex audio success response.

All errors contain `{ "error": "Human-readable explanation", "code": "STABLE_ERROR_CODE" }`
with an appropriate HTTP status. Clients written for v0.1 may continue reading only `error`.

The frontend owns microphone STT and audio playback. Moderator, Sarah, and David
continue to use browser TTS. Alex audio may be generated by the backend's scoped
ElevenLabs adapter. The backend owns session state, turn choice, transcript, AI
prompts, and the active AI turn lifecycle. The frontend must never imply that the
backend directly detected a microphone interruption.

## Endpoints

- `GET /health` -> `200 { "ok": true, "service": "gd-arena-api" }`
- `POST /sessions` with `{ "topic": "...", "durationMinutes": 5 }` ->
  `{ "sessionId": "...", "turn": { "turnId": "...", "speaker": "Moderator", "text": "..." } }`
  `durationMinutes` is optional, defaults to `5`, and must be an integer from 1
  through 60. The success response remains unchanged.
- `POST /sessions/:id/messages` with
  `{ "text": "...", "interruptTurnId": "optional-active-turn-id" }` ->
  `{ "turn": { "turnId": "...", "speaker": "Alex|Sarah|David|Moderator", "text": "..." } }`.
  When `interruptTurnId` is present, the backend atomically cancels that exact
  active turn before recording the student contribution and generating a response.
  A clear deterministic ending command instead returns `{ "endRequested": true }`
  without starting Gemini generation. The client must then call the existing `/end`
  endpoint to obtain the report.
- `POST /sessions/:id/next` with `{ "interruptTurnId": "optional-active-turn-id" }` ->
  `{ "turn": { "turnId": "...", "speaker": "...", "text": "..." } }`
  A generated turn may also include `{ "interruption": { "afterMs": 1800 } }`.
  This is a backend-owned, optional AI-interjection plan; the client cancels the
  exact active turn before requesting the interjection with `interruptTurnId`.
- `POST /sessions/:id/turns/:turnId/audio` with `{}` -> binary `audio/mpeg`.
  This is available only while the referenced turn is the session's active Alex
  turn. The endpoint accepts no text, speaker, voice ID, or provider options from
  the client; it synthesizes the already stored turn text. Successful responses
  use `Cache-Control: private, no-store`. Errors retain the standard JSON shape.
- `POST /sessions/:id/turns/:turnId/ack` with
  `{ "event": "completed|cancelled", "requestContinuation": true }` ->
  `{ "turnId": "...", "event": "completed|cancelled", "state": "LISTENING" }`
  The optional `requestContinuation` flag adds `nextAction: "generate|listen"`.
  A completed turn also includes bounded `continuationDelayMs` and a
  `participationWindow` boolean so the client can pause briefly without requiring
  a manual Continue action. A cancelled turn returns `nextAction: "listen"`.
  Omitting it preserves the original acknowledgment response exactly.
- `POST /sessions/:id/end` with `{ "cancelPendingTurn": false }` -> the evaluation
  report described below. `cancelPendingTurn: true` is reserved for the frontend's
  generation/end race, where a generated turn was never presented for playback.

The v0.1 success response formats for session creation, messages, and next turns
are unchanged. The end response retains `transcript` and `feedback` while adding
Phase B3 evaluation fields.

## Turn lifecycle

The backend uses one authoritative session state:

`READY -> SPEAKING -> LISTENING -> GENERATING -> SPEAKING`

`LISTENING -> ENDED` is terminal. A newly created session moves through `READY`
to `SPEAKING` when its moderator introduction is returned.

While `SPEAKING`, the frontend must acknowledge the active `turnId` before calling
`/messages`, `/next`, or `/end`:

- `completed` records successful browser playback and moves to `LISTENING`.
- `cancelled` invalidates and removes the uncompleted active turn, preserves all
  previously completed transcript entries, and moves to `LISTENING`.

To handle a microphone interruption, the frontend immediately cancels browser
speech, acknowledges `cancelled`, and begins manual recognition. A typed student
interruption can send the active `interruptTurnId` with the message so cancellation
and the new contribution are authoritative in one backend operation. Duplicate or
stale turn events return `409`. A Gemini failure restores a consistent state and
never restores an invalidated playback turn.

After successful playback, clients may opt into backend-authorized automatic
continuation. Completed AI turns return `nextAction: "generate"`; normal turns use
a short delay, while every third consecutive AI contribution uses a four-second
student participation window. Typing or starting the microphone cancels the
client's single pending timer. If the student remains silent, that same timer
requests the next turn without polling. Cancelled turns return `listen` and never
continue automatically. AI interjections are infrequent, apply only to longer
participant turns, start their delay only after audio playback has actually begun,
cancel exact turn IDs, exclude the interrupted speaker from the immediate response,
and cannot chain recursively.

Each session has a backend-owned deadline established at creation. At the
deadline, the backend uses the existing ending lifecycle, prevents new turns,
cancels any unfinished active AI turn, preserves completed transcript entries,
and caches the resulting report. The frontend countdown calls `/end` to retrieve
that report and navigate, but it is not the authority for enforcing the limit.
Attempts to generate another turn after expiry return `409` with
`SESSION_DEADLINE_REACHED` while automatic closure settles.

Clear ending commands mark the authoritative session as ending, block subsequent
debate generation, and are excluded from the evaluative transcript. Ambiguous,
negated, quoted, or explanatory uses of ending language do not close the session.
If `/end` arrives during `GENERATING`, it waits for that bounded request to settle,
discards the stale AI result, preserves any substantive student turn, and closes
once. If generation wins the network race and creates an unseen active turn, the
frontend sends `cancelPendingTurn: true`; the backend records cancellation for its
exact turn ID before closing. Visible `SPEAKING` playback must still be cancelled
and acknowledged normally before `/end`.

Requesting Alex audio does not change discussion state. The frontend plays the
returned audio and acknowledges `completed` only after the matching browser Audio
element ends. An intentional interruption stops that exact audio and acknowledges
`cancelled`. Fetch failures, missing ElevenLabs configuration, provider rate limits,
or browser playback failures leave the turn active so the frontend can use Alex's
browser-speech fallback. Repeated audio requests for the same active turn share a
bounded temporary result; acknowledgment releases it. No generated audio is stored
permanently.

Alex voice errors include `ALEX_VOICE_NOT_CONFIGURED`,
`ALEX_VOICE_INVALID_CREDENTIALS`, `ALEX_VOICE_INSUFFICIENT_CREDITS`,
`ALEX_VOICE_INACCESSIBLE`, `ALEX_VOICE_PERMISSION_DENIED`,
`ALEX_VOICE_RATE_LIMITED`, `ALEX_VOICE_TIMEOUT`,
`ALEX_VOICE_UPSTREAM_REJECTED`, `ALEX_VOICE_UPSTREAM_FAILURE`,
`ALEX_VOICE_INVALID_RESPONSE`, `ALEX_VOICE_REQUEST_LIMIT`, and
`ALEX_VOICE_NOT_AVAILABLE`. Provider failures remain recoverable `503` responses
so the frontend can fall back to browser speech. Stale or completed turn IDs use
`STALE_TURN_ID`. Provider credentials are server-only and never appear in API
responses.

## Evaluation report

`POST /sessions/:id/end` closes the discussion and returns:

```json
{
  "sessionId": "uuid",
  "status": "complete|partial|insufficient_evidence",
  "overallScore": 7.5,
  "transcript": [
    { "turnId": "uuid", "speaker": "Student", "text": "...", "timestamp": "..." }
  ],
  "metrics": {
    "totalStudentTurns": 2,
    "totalAiParticipantTurns": 3,
    "studentContributionPercentage": 24.5,
    "totalStudentWords": 38,
    "totalDiscussionWords": 155,
    "perSpeaker": {
      "Student": { "turns": 2, "words": 38, "wordPercentage": 24.5 }
    },
    "discussionDurationSeconds": 84.2,
    "averageStudentContributionWords": 19
  },
  "feedback": [
    {
      "category": "opening_contribution",
      "status": "assessed|not_assessed",
      "score": 7,
      "explanation": "Concise evidence-based explanation.",
      "strength": "Specific demonstrated strength.",
      "improvementOpportunity": "Specific area to strengthen.",
      "actionableNextStep": "Concrete action for the next discussion.",
      "improvement": "Specific next action.",
      "evidenceTurnIds": ["actual-transcript-turn-id"]
    }
  ],
  "summary": "Concise overall assessment.",
  "recommendations": ["Concrete recommendation."]
}
```

`overallScore` is the one-decimal arithmetic mean of the existing assessed
category scores on the same 0–10 scale. Unassessed categories are excluded. It
is `null` for partial reports and when no categories have sufficient evidence.
A partial report also includes a sanitized `evaluationError` with `code`,
`category`, `retryable`, and a user-safe `message`; it never contains credentials,
transcript content, or raw provider responses.

Feedback diagnostics distinguish missing configuration, invalid credentials,
permission denial, unavailable models, rate/quota limits, timeouts, upstream or
network failures, empty provider responses, malformed JSON, schema mismatches,
invalid transcript evidence, incomplete responses, and unexpected internal errors.
Feedback generation may retry once for a timeout, network failure, temporary
upstream failure, or empty provider response. Authentication, permission, quota,
request-schema, parsing, and validation failures are not retried. Repeated `/end`
calls still reuse the cached report and never create duplicate Gemini costs.

The six feedback categories are `opening_contribution`,
`argument_quality_and_relevance`, `building_on_others`,
`listening_and_responsiveness`, `handling_disagreements_and_interruptions`, and
`closing_contribution`. A `not_assessed` category has `score: null` and no evidence
IDs. All assessed evidence IDs refer to real stored transcript turns. Together
these categories cover communication clarity, argument quality, critical thinking,
listening and responsiveness, confidence and participation, and collaboration
through respectful disagreement. Strengths, improvement opportunities, and
actionable next steps shown by the frontend come from these validated category
fields rather than another score or a client-side placeholder.

`studentContributionPercentage` and each per-speaker percentage are based on word
counts across the stored transcript, including Moderator turns. They are not audio
speaking-time measurements. `totalAiParticipantTurns` counts Alex, Sarah, and David,
not Moderator. No audio duration is inferred or returned.

`complete` means Gemini feedback passed validation. `partial` means deterministic
metrics and the transcript are available but AI evaluation failed validation or was
unavailable. `insufficient_evidence` means there were no student turns to evaluate.
Repeated end requests return the cached report and do not trigger another Gemini call.

## Fixed roles and ownership

Names are fixed: Alex, Sarah, David, Moderator, and Student. Inputs must be
validated. Secret API keys must never appear in a response. Each AI participant
has distinct instructions, and Moderator is a separate role.

Laptop A owns `frontend/**` and frontend `.env`. Laptop B owns `backend/**` and
this contract. Both review contract changes before implementing them.
